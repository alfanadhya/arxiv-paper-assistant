Context window policy

arXiv paper assistant · as of 22 November 2026 · model qwen3:4b served locally by Ollama

1Window size

  • 8,192 tokens, set in the configuration (OLLAMA_NUM_CTX=8192). Every model call in the app uses the same window.
  • With OLLAMA_NUM_CTX=auto (the default when the setting is absent) the app reads the model’s own maximum from Ollama at start-up and caps it at 16,384 (NUM_CTX_MAX), because Ollama reserves GPU memory for the whole window each time the model loads. Ollama reports 262,144 for qwen3:4b, so the cap decides. All budgets below are derived from the window size, so they follow it if the model changes.
  • At start-up the app checks that the loaded model really runs with this window and reloads it if not. The start-up message states the window and where it came from.

3Room reserved for the answer

  • Research assistant (agent): at most 4,096 generated tokens per step, covering both the thinking and the answer. The written answer itself is asked to stay under about 200 words (350 for a comparison of papers).
  • title= route: no model call for the ranking (title similarity and the reranker decide), so it uses the window only for the short title check.
  • search= route (ranking call): the output room is calculated for each call:
output room = window − prompt estimate − margin
margin      = 10% of the prompt estimate, at least 256, at most 512 tokens
prompt estimate = characters / 3.5 (on the safe side)
  • The model may use the whole output room, so prompt plus output can never overflow the window. There is no fixed output cap (RANKING_MAX_OUTPUT=0).
  • A prompt is sent only if its output room is at least 2,000 tokens (RANKING_OUTPUT_RESERVE). With an 8,192 window that allows prompts of up to 5,680 tokens.
  • If N+2 papers would leave less, the app sends fewer: N+1, N, … down to 1. If even one paper leaves less, the model is not called and the reranker’s order is shown; the diagnostics say why.
  • Because the margin is capped at 512, the 2,000-token minimum holds for any window size.

When N+2 fits (8,192 window)

The slider therefore stops at N = 5: N+2 always fits, and even the worst-case prompt leaves about 2,700 tokens for the model’s thinking. A 16,384 window raises the limit to 13,872 tokens.

4Monitoring

  • Every model call records its prompt and output tokens as reported by Ollama.
  • The diagnostics panel shows each step against the window, e.g. agent step 2: prompt 3,199 + output 698 = 3,897 / 8,192 tokens (48%), the peak use per question, and for each ranking call the output room it was given.
  • The same figures are saved with every evaluation case, which is the basis for the statistics below.
