Context window policy

arXiv paper assistant · as of 21 November 2026 · model qwen3:4b served locally by Ollama

1Window size

  • 8,192 tokens, set in the configuration (OLLAMA_NUM_CTX=8192). Every model call in the app uses the same window.
  • Without that setting the app reads the model’s own maximum from Ollama at start-up and caps it at 16,384 (NUM_CTX_MAX), because Ollama reserves GPU memory for the whole window each time the model loads. All budgets below are derived from the window size, so they follow it if the model changes.
  • At start-up the app checks that the loaded model really runs with this window and reloads it if not.

2What goes into the window

ContentLimitWhy
Candidate papers per search5 “N+2”: the reranker’s top 3 plus two more, so the model has a choice without a long prompt
Abstract per paper in search results700 characters Enough to judge relevance; the full abstract is fetched only on request (get_paper)
Authors per paper5 in search results, 40 via get_paper Long author lists are rarely needed and cost many tokens
Conversation historylast 10 question/answer pairs Supports follow-up questions; older turns are dropped
Model “thinking”not kept Removed from answers before they enter the history (as Qwen3’s guidance recommends)
Tool rounds per question (research assistant)at most 4 Each round adds tool results to the prompt; the cap bounds growth

3Room reserved for the answer

  • Research assistant (agent): at most 4,096 generated tokens per step, covering both the thinking and the answer. The written answer itself is asked to stay under about 200 words (350 for a comparison of papers).
  • search= route (ranking call): before sending, the app estimates the prompt size (about 3.5 characters per token, on the safe side) and checks that the prompt plus 3,000 tokens of output room fits the window. If 5 candidates do not fit, it sends 4 (N+1). The output cap is then set to whatever the window has left after the prompt and a margin, at most 4,096, so the output can never overflow the window.
  • title= route: no model call for the ranking (title similarity and the reranker decide), so it uses the window only for the short title check.

4Monitoring

  • Every model call records its prompt and output tokens as reported by Ollama.
  • The diagnostics panel shows each step against the window, e.g. agent step 2: prompt 3,199 + output 698 = 3,897 / 8,192 tokens (48%), and the peak use per question.
  • The same figures are saved with every evaluation case, which is the basis for the usage statistics.
Measured usage across the evaluation runs (by route: peak and per-step use, median and worst case against 8,192 tokens) will be added once the current search= evaluation run has finished.
